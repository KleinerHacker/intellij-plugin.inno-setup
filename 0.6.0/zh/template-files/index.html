    Inno Setup 模板文件

    除了安装程序脚本（.iss）和语言文件（.isl）之外，该插件还支持 Inno Setup 模板文件（.ist）。模板是一段可复用的自由文本片段，旨在通过 ISPP 的 #include 指令拉入脚本。它让你能够把公共的节、指令或预处理器定义从单个脚本中提取出来，并在多个安装程序之间共享。

    什么是模板

    .ist 文件是自由文本。与 .iss 和 .isl 文件不同，它没有必需的结构，也从不作为独立脚本进行校验：

    • 它可以包含完整的节（[Files]、[Registry]…）、部分节、零散的指令行、ISPP 预处理器指令（#define、#include …），或它们的任意组合。
    • 它甚至可以包含在真正的 .iss 脚本中无效的内容——因为模板只是一个构建块，而不是完整的安装程序。因此插件绝不会在 .ist 文件中报告解析错误或校验警告。
    • 它的含义只有在被包含进宿主脚本后才确定，在那里它会在周围 .iss 内容的上下文中被解释。

    这与 Inno Setup 预处理器（ISPP）处理 #include 目标的方式一致：被包含的文本会按原样拼接进脚本，因此一个片段的正确性始终取决于它被包含的位置。

    使用模板

    模板通过 #include 使用。由于文件扩展名对 ISPP 无关紧要，.ist 模板的包含方式与任何其他文件完全相同：

    ; main.iss
[Setup]
AppName=My Program
AppVersion=1.5

#include "common-files.ist"
#include "registry-defaults.ist"

    ; common-files.ist （模板，自由文本）
[Files]
Source: "readme.txt"; DestDir: "{app}"
Source: "license.txt"; DestDir: "{app}"

    分析宿主脚本时，插件会解析 #include 并将模板的节合并进有效脚本——即 main.iss 完全解析包含后的视图。来自宿主和被包含模板的同名节会统一为单个块，因此上面的示例的行为就如同 [Files] 条目直接写在 main.iss 中一样。

    模板可以传递地包含其他模板（或脚本）；包含循环会被检测并安全地打断。

    编辑功能

    语法高亮

    模板使用专用的高亮器，使熟悉的 Inno Setup 结构即使在自由文本片段中也保持可读：

    • 节标题（[Files]、[Registry]…）作为结构标记被高亮
    • 预处理器行（#define、#include…）被识别为唯一的结构化元素，并通过完整的 ISPP 语言注入进行高亮（见下文）

    预处理器注入

    模板中的每一行 #… 都携带一个注入的 ISPP 片段，与 .iss/.isl 文件中完全相同。在这些行内你可以获得完整的预处理器语言支持——对 #define、#include、表达式和内置函数的补全、引用和内联文档。

    节名补全

    输入 [ 会打开一个补全弹窗，提供所有已知的 Inno Setup 节名。由于模板是自由文本，没有文件类型或版本过滤，因此始终建议完整的节集合（不同于 .iss/.isl 中受上下文限制的列表）。接受建议会自动插入闭合的 ]。

    括号匹配

    为 [ ]（结构性节括号）和 ( ) 提供匹配，因此在模板片段中导航和配对的方式与脚本中相同。

    包含路径补全与导航

    在 #include "…" 指令内，.ist 模板会与其他可包含文件一起被提供用于补全，并且路径会解析到模板文件以实现跳转到定义导航。

    模板刻意不具备的功能

    由于 .ist 文件是有意保持无结构的片段，几项仅限脚本的功能对它被关闭：

    • 无校验/注解器——损坏的或脱离上下文的 Inno Setup 内容绝不会产生 ERROR 或 WARNING 高亮。
    • 无结构视图——模板没有可显示的有保证的节树。

    这些功能在宿主 .iss/.isl 脚本上仍然可用，在那里模板的内容会在其真实的、解析包含后的上下文中被分析。

    创建模板

    从 IDE 的新建文件菜单使用 新建 → Inno Setup 模板。由于模板是自由文本，对话框只询问文件名并创建一个空的 .ist 文件——不会生成内容骨架。
