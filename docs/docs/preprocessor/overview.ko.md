# Inno Setup 전처리기(ISPP)

Inno Setup 전처리기(ISPP)는 스크립트가 컴파일되기 **전에** 실행되며, 지시문, 매크로, 표현식을 사용하여 스크립트를 생성하거나 변경할 수 있습니다. 플러그인은 전처리기 줄을 자체 언어로 주입하므로
전용 강조 표시, 완성, 검증, 이름 바꾸기, 사용 찾기 지원을 받습니다. 이 섹션은 공식
[Inno Setup 전처리기 문서](https://jrsoftware.org/ishelp/topic_isppoverview.htm)의 구조를 따릅니다.

---

## 전처리기 지시문이란?

지시문은 `#`로 시작하는 줄입니다. 컴파일 시점에 평가되며 최종 설치 프로그램에는 나타나지 않습니다. 플러그인은 번들된 ISPP 사양에 대해 키워드를 검증합니다. 알 수 없는 지시문(사양에 정의되지 않은 것)은
오류로 표시됩니다(대소문자 구분 안 함). 알 수 없는 섹션/플래그/상수 검사와 동일합니다.

---

## 줄 연속

백슬래시로 끝나는 지시문은 Inno Setup 전처리기와 마찬가지로 다음 줄로 이어집니다. 플러그인은 그러한 지시문의 모든 물리적 줄을 **하나의** 지시문으로 취급합니다. 강조 표시, 완성, 검증, 빠른
문서, 매개변수 정보, 이름 바꾸기가 줄바꿈을 넘어 동작합니다.

```iss
#define InstallerName "MyApp " + \
                      MyAppVersion + \
                      " Setup"
```

백슬래시 뒤에는 공백만 올 수 있습니다. 뒤따르는 스페이스와 탭은 허용되며 포매터가 제거합니다. 그 외의 문자가 오면 연속이 아닙니다.

---

## 지원되는 지시문

| 그룹       | 지시문                                                                             |
|----------|---------------------------------------------------------------------------------|
| 정의       | `#define`, `#undef`, `#dim`, `#redim`                                           |
| 포함       | `#include`, `#file`                                                             |
| 출력       | `#emit`, `#expr`, `#insert`, `#append`                                          |
| 조건       | `#if`, `#elif`, `#else`, `#endif`, `#ifdef`, `#ifndef`, `#ifexist`, `#ifnexist` |
| 루프 및 매크로 | `#for`, `#sub`, `#endsub`                                                       |
| 기타       | `#pragma`, `#error`                                                             |

모든 지시문 키워드는 강조 표시되고 완성되며(`#` 뒤) 사양에 대해 검증됩니다. 각 지시문에는 전용 페이지가 있습니다:

- [`#define`](define.md) — 매크로 선언 및 사용, 그리고 표준 사전 정의 변수
- [`#undef`](undef.md) — 이전에 정의된 매크로 제거
- [`#dim` / `#redim`](arrays.md) — 배열 매크로 선언 및 크기 조정
- [`#include` / `#file`](include.md) — 다른 파일의 내용 붙여넣기 / 파일 읽기
- [`#emit` / `#expr` / `#insert` / `#append`](output.md) — 식을 평가하여 출력(또는 출력 안 함)
- [`#if` / `#ifdef` / …](conditionals.md) — 조건부 컴파일
- [`#for`](for.md) — C 스타일 루프로 지시문 반복
- [`#sub` / `#endsub`](sub.md) — 재사용 가능한 서브루틴 정의
- [`#pragma`](pragma.md) — 전처리기 제어(옵션, 진단, 구분 기호 등)
- [`#error`](error.md) — 메시지와 함께 컴파일 중단

---

## 인라인 출력 `{#…}`

일반 스크립트 줄 안에서 `{#expr}`는 `{#emit expr}`의 인라인 형식입니다. 전처리기는 표현식을 평가하고 자리 표시자를 해당 값으로 바꿉니다. 표현식은 일반적으로 매크로 또는 사전 정의 변수입니다.
자세한 내용과 이 방식으로 사용할 수 있는 사전 정의 변수는 [`#define`](define.md)을 참조하세요.

## 명령줄에서 오는 심볼(`/D`)

ISCC는 `/D<이름>[=<값>]`으로 스크립트 외부에서 심볼을 정의할 수 있으며, 이는 디버그와 릴리스를 전환하는 일반적인
방법입니다. 플러그인은 현재 선택된 실행 구성의 **빌드 구성**([실행 구성](../run-configuration.ko.md) 참조)에서 이
심볼을 가져오므로, 스크립트 맨 위에 작성한 `#define`처럼 동작합니다:

```ini
; 빌드 구성 옵션:  /DDEBUG /DVERSION=2

#ifdef DEBUG
[Setup]
AppName=My App (Debug)
#endif

[Setup]
AppVerName=My App {#VERSION}
```

- `#ifdef`/`#if` 조건이 판정되므로 분기는 판정 불가 상태 대신 흐리게 표시됩니다
- `{#Name}`은 "알 수 없는 상수" 오류 없이 해당 심볼을 출력하며 코드 완성에도 제공됩니다
- `#define`/`#if` 식의 식별자는 미해결로 보고되지 않고 해석됩니다. 숫자 값(`/DVERSION=2`)은 `int`가 되고,
  값이 없는 `/DDEBUG`는 `any`로 남습니다
- 다른 실행 구성을 선택하거나 그 빌드 구성을 편집하면 심볼이 즉시 바뀌며, 더 이상 정의되지 않은 이름은 다시
  알 수 없는 이름이 됩니다

스크립트 안에 선언이 없으므로 이동할 대상이 없습니다: 정의로 이동과 사용처 찾기는 적용되지 않습니다.

## `#include` 작업

`#include "file"` 경로는 참조된 `.iss` 파일로 해석됩니다(포함하는 스크립트의 디렉터리 기준 상대 경로,
절대 경로는 그대로 사용). **Ctrl+B** / **Cmd+B** 로 파일로 이동할 수 있으며 입력 중에 경로가 완성됩니다.
include 작업을 더 쉽게 해 주는 두 가지 편집기 동작이 있습니다.

- **`#include` 내용 인라인 삽입** — 기존 파일로 해석되는 `#include` 줄에 캐럿을 두면 인텐션
  (**Alt+Enter**)이 해당 줄을 그 파일의 내용 그대로 바꿉니다. 한 단계만 펼치며, 삽입된 텍스트 안의
  중첩된 `#include` 줄은 그대로 유지됩니다. 이후 인라인으로 삽입한 포함 파일을 삭제할지 묻습니다
  (기본값: 아니요).
- **선택 영역을 `#include` 파일로 추출** — 한 줄 이상을 선택하고 인텐션을 실행하면 현재 스크립트 옆에
  새 파일로 분리합니다. 파일 이름을 묻고(기존 파일을 덮어쓰기 전에도 확인) 선택한 전체 줄을 새 파일의
  `#include`로 바꿉니다.

참조된 파일을 IDE에서 **이름 바꾸기 또는 이동**하면 `#include` 경로가 자동으로 갱신되어 파일을 계속
가리킵니다.

### 검증

`#include` 줄 자체도 검사됩니다. 누락되었거나 존재하지 않는 파일, 리터럴이 아니거나 빈 경로는 오류로
표시됩니다. 포함된 파일 **내부**에서 감지된 문제(알 수 없는 지시문, 플래그, 정의되지 않은 상수, 경고)는
포함하는 스크립트의 `#include` 줄에 표시되며, 필수 섹션 검사도 include가 제공하는 내용을 올바르게
반영합니다.

### 유효 스크립트 표시

**유효 스크립트 표시(Show Effective Script)** 동작은 `#include`가 완전히 해석된(모든 include가 인라인된)
스크립트를 읽기 전용 탭에서 열어 컴파일러가 실제로 보는 내용을 확인할 수 있게 합니다.

## 편집기 지원

- 지시문, 매크로 이름, 범위 키워드, 인라인 `{#…}` 참조에 대한 **구문 강조 표시**
- 지시문 키워드, `#define`/`#undef` 범위 키워드, `#define` 및 값을 가진 사전 정의 변수, 내장 함수의
  **완성** — `#if`/`#elif` 조건 내부 포함
- 알 수 없는 지시문, 알 수 없는 `{#…}` 참조, 사용되지 않는 `#define`, 손상되었거나 문제가 있는 `#include`
  줄, `#if … #endif` 블록 구조(누락된 `#endif`, 떠도는 `#elif`/`#else`/`#endif`, 조건 없는 `#if`),
  조건 내 리터럴 불리언의 **검증**
- `#define` 및 그 모든 사용(`{#Name}` 참조, `#undef`, `#if`/`#elif` 조건 내 식별자)에 걸친 **이름 바꾸기**와
  **사용 찾기**
- 단일 섹션 내부 또는 모든 섹션 외부에 완전히 있는 `#if … #endif` 블록의 **접기**
- **유효 스크립트 표시** — `#include`가 완전히 해석된 스크립트를 읽기 전용 탭에서 확인
- `#include`의 **인라인** 및 **추출** 인텐션, 이름 바꾸기/이동 시 경로 자동 갱신
