# Inno Setup 预处理器（ISPP）

Inno Setup 预处理器（ISPP）在脚本编译**之前**运行，允许你通过指令、宏和表达式生成或修改脚本。插件将预处理器行作为独立语言注入，因此它们获得专门的高亮、补全、验证、重命名和查找用法支持。本节遵循官方
[Inno Setup 预处理器文档](https://jrsoftware.org/ishelp/topic_isppoverview.htm)的结构。

---

## 什么是预处理器指令？

指令是以 `#` 开头的行。它在编译时求值，且不会出现在最终安装程序中。插件会根据其捆绑的 ISPP
规范验证关键字——未知指令（规范中未定义的）会被标记为错误（不区分大小写），与未知节/标志/常量检查一致。

---

## 行继续

以反斜杠结尾的指令会继续到下一行——与 Inno Setup 预处理器的处理方式完全一致。插件将此类指令的所有物理行视为**一个**指令：高亮、补全、验证、快速文档、参数信息和重命名都可跨换行工作。

```iss
#define InstallerName "MyApp " + \
                      MyAppVersion + \
                      " Setup"
```

反斜杠之后只能跟空白字符；末尾的空格和制表符会被容忍并由格式化程序移除，而跟随其他字符则不构成行继续。

---

## 支持的指令

| 分组   | 指令                                                                       |
|------|--------------------------------------------------------------------------|
| 定义   | `#define`、`#undef`、`#dim`、`#redim`                                       |
| 包含   | `#include`、`#file`                                                       |
| 输出   | `#emit`、`#expr`、`#insert`、`#append`                                      |
| 条件   | `#if`、`#elif`、`#else`、`#endif`、`#ifdef`、`#ifndef`、`#ifexist`、`#ifnexist` |
| 循环与宏 | `#for`、`#sub`、`#endsub`                                                  |
| 其他   | `#pragma`、`#error`                                                       |

所有指令关键字都会被高亮、补全（`#` 之后）并根据规范验证。每个指令都有各自的页面：

- [`#define`](define.md) — 声明和使用宏，以及标准预定义变量
- [`#undef`](undef.md) — 移除先前定义的宏
- [`#dim` / `#redim`](arrays.md) — 声明和调整数组宏的大小
- [`#include` / `#file`](include.md) — 粘贴另一个文件的内容 / 读取文件
- [`#emit` / `#expr` / `#insert` / `#append`](output.md) — 计算表达式并输出（或不输出）
- [`#if` / `#ifdef` / …](conditionals.md) — 条件编译
- [`#for`](for.md) — 以 C 风格循环重复执行指令
- [`#sub` / `#endsub`](sub.md) — 定义可重用的子例程
- [`#pragma`](pragma.md) — 控制预处理器（选项、诊断、分隔符……）
- [`#error`](error.md) — 中止编译并显示消息

---

## 内联输出 `{#…}`

在普通脚本行内，`{#expr}` 是 `{#emit expr}`
的内联形式：预处理器计算表达式并用其值替换占位符。表达式通常是宏或预定义变量。详情及可通过此方式使用的预定义变量，请参阅 [
`#define`](define.md)。

---

## 来自命令行的符号（`/D`）

ISCC 支持用 `/D<名称>[=<值>]` 从脚本外部定义符号，这是在 Debug 与 Release 之间切换构建的常用方式。
插件会从当前所选运行配置的**构建配置**（参见[运行配置](../run-configuration.zh.md)）中读取这些符号，
使其表现得如同写在脚本最开头的 `#define`：

```ini
; 构建配置选项:  /DDEBUG /DVERSION=2

#ifdef DEBUG
[Setup]
AppName=My App (Debug)
#endif

[Setup]
AppVerName=My App {#VERSION}
```

- `#ifdef`/`#if` 条件可据此判定，分支会被淡显而不是保持“无法判定”
- `{#Name}` 可以输出该符号且不会报“未知常量”错误，同时会出现在代码补全中
- `#define`/`#if` 表达式中的标识符会解析到它，而不再被报为未解析；数值（`/DVERSION=2`）使其为 `int`，
  无值的 `/DDEBUG` 则保持 `any`
- 选择另一个运行配置或修改其构建配置后，符号会立即切换；不再被定义的名称会重新变为未知

由于该符号在脚本中没有声明，因此没有可跳转的目标：转到定义和查找用法对它不适用。

## 使用 `#include`

`#include "file"` 路径会解析到所引用的 `.iss` 文件（相对于包含脚本所在目录；绝对路径按原样使用）。
**Ctrl+B** / **Cmd+B** 可跳转到该文件，输入时还会补全路径。两个编辑器操作让处理 include 更轻松：

- **内联 `#include` 内容** — 当光标位于可解析到现有文件的 `#include` 行时，意图操作（**Alt+Enter**）
  会用该文件的原始内容替换该行。只展开一层；插入文本中嵌套的 `#include` 行保持原样。随后会询问是否
  删除已内联的被包含文件（默认：否）。
- **将选定内容提取到 `#include` 文件** — 选择一行或多行并执行意图操作，即可将其移动到当前脚本旁的新
  文件中。会请求输入文件名（在覆盖已有文件前也会确认），并将选定的整行替换为对该新文件的 `#include`。

当在 IDE 中**重命名或移动**所引用的文件时，`#include` 路径会自动更新以继续指向该文件。

### 验证

`#include` 行本身也会被检查：缺失或不存在的文件，以及非字面量或空路径，都会被标记为错误。在被包含文件
**内部**检测到的问题（未知指令、标志、未定义常量、警告）会显示在包含脚本的 `#include` 行上，必需节检查
也会正确计入由 include 提供的内容。

### 显示有效脚本

**显示有效脚本（Show Effective Script）**操作会在只读标签页中打开完全解析 `#include`（所有 include 均内联）
后的脚本，便于你查看编译器实际看到的内容。

## 编辑器支持

- 对指令、宏名称、作用域关键字和内联 `{#…}` 引用的**语法高亮**
- 指令关键字、`#define`/`#undef` 作用域关键字、`#define` 与带值预定义变量以及内置函数的**补全** ——
  包括 `#if`/`#elif` 条件内部
- 对未知指令、未知 `{#…}` 引用、从未使用的 `#define`、损坏或有问题的 `#include` 行、`#if … #endif`
  块结构（缺少 `#endif`、游离的 `#elif`/`#else`/`#endif`、无条件的 `#if`）以及条件中的字面布尔值的**验证**
- 跨 `#define` 及其所有用法（`{#Name}` 引用、`#undef`、`#if`/`#elif` 条件中的标识符）的**重命名**和
  **查找用法**
- 对完全位于单个节内或完全位于所有节之外的 `#if … #endif` 块的**折叠**
- 针对 `#include` 的**内联**与**提取**意图操作，并在重命名/移动时自动更新路径
- **显示有效脚本**，在只读标签页中查看完全解析 `#include` 后的脚本
